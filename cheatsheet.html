Del pseudocódigo
al easing

Quince conceptos en el orden en que se necesitan. Cada uno usa lo que viene antes; ninguno usa lo que viene después. Si algo no se entiende, la pieza que falta está más arriba.

Nada previoRequiere todo lo anterior
Cómo usar esto: búscalo cuando ya estés atorado en algo, no antes. Cada concepto trae qué es, cómo se escribe y una demo que puedes mover. Lo que está en oscuro es lo que ve la máquina; lo que está en claro es para ti.
Bloque A

Antes de tocar el teclado

No requiere saber programar. Es la parte que casi siempre nos saltamos y es la que decide si el código sale o no.

01

Pseudocódigo

Requierenada

Escribir los pasos de tu programa en español, en orden, sin sintaxis. Es el guion antes del rodaje.

Ya lo hacesNo empiezas a animar sin storyboard. Esto es el storyboard del código: define qué pasa y en qué orden, sin preocuparte por cómo se escribe.

No se ejecuta y no tiene reglas. La única regla útil: un paso por línea y verbos concretos. Si un paso te sale vago («hacer que se vea bien»), es que todavía no sabes qué quieres.

02
Terminal

      
Requierenada

      
Le das órdenes a tu computadora escribiendo en vez de haciendo clic. Siempre estás parado en una carpeta, y los comandos actúan sobre esa carpeta.

      
La única idea que importaLa terminal siempre está «dentro» de una carpeta. El 90% de los errores de principiante es correr el comando correcto en la carpeta equivocada. Antes de cualquier cosa: pwd.


      
Comandos que vas a usar todos los días

      

        
pwd¿Dónde estoy? Imprime la ruta de la carpeta actual.

        
ls¿Qué hay aquí? Lista archivos y carpetas. En Windows/PowerShell: dir.

        
cd carpetaEntrar a esa carpeta.

        
cd ..Salir un nivel hacia arriba.

        
mkdir nombreCrear carpeta.

        
touch archivo.jsCrear archivo vacío (macOS/Linux).

        
code .Abrir esta carpeta en VS Code. El punto significa «la carpeta donde estoy».

        
clearLimpiar la pantalla. No borra nada real.

        
Ctrl + CDetener lo que esté corriendo. Tu botón de pánico.

        
↑Flecha arriba: recupera el comando anterior. Ahorra media vida.

03
git

      
RequiereTerminal

      
Le toma fotos a tu proyecto. Cada foto (commit) queda guardada con fecha y mensaje, y siempre puedes volver a cualquiera.

      
VersionesEs el proyecto_final_v3_BUENO_ahora_sí.zip, pero hecho bien: una sola carpeta con todo su historial adentro.

      

        
git ≠ GitHub. git corre en tu compu. GitHub es el sitio donde subes una copia. Por eso son dos pasos distintos: commit guarda en tu compu, push sube a GitHub. Puedes hacer 20 commits sin internet.

      


      
Los cuatro pasos del ciclo normal

      

        
mueve el archivo por las zonas

(git add)

            
Repo local
(git commit)

(git push)

          

          

            
            
            
            
            
          

          

        

      


      
Comandos

      

        
git initUna sola vez por proyecto. Empieza a rastrear esta carpeta.

        
git status¿Cómo voy? Qué cambió y qué está listo para commit. Úsalo entre cada paso.

        
git add .Selecciona todos los cambios para la próxima foto.

        
git commit -m "mensaje"Toma la foto en tu compu. El mensaje describe qué hiciste, en presente: «agrega menú móvil».

        
git pushSube tus commits a GitHub.

        
git pullBaja lo que otros subieron. Hazlo antes de empezar a trabajar en equipo.

        
git clone urlCopia un repo de GitHub a tu compu.

        
git log --onelineVer el historial compacto. Sal con q.

        
git checkout -b ramaCrear una rama para experimentar sin romper lo que ya funciona.

      

      
Regla práctica: commit cada vez que algo funcione, aunque sea chiquito. Un commit gigante al final del día no sirve para regresar.

    


    
    

      
04
npm

      
RequiereTerminal

      
Instala código que otras personas ya escribieron. Escribes un comando y la librería queda lista para usarse en tu proyecto.

      
EquivalenteEs tu carpeta de plugins y presets, pero versionada: el proyecto guarda por escrito qué necesita, y cualquiera puede reconstruirlo con un comando.

      

        
    
          
  • package.json — la lista de ingredientes. Este sí se sube a git.
    • 
          
  • node_modules/ — los ingredientes ya descargados. Pesa muchísimo. Nunca se sube a git.
    • 
        

        
Por eso al clonar un repo ajeno corres npm install sin argumentos: lee el package.json y reconstruye la carpeta pesada.

      


      
Comandos

      

        
npm init -yCrea el package.json con valores por defecto. Primer paso de un proyecto nuevo.

        
npm install gsapInstala una librería y la anota en package.json.

        
npm installSin nombre: instala todo lo que pide el package.json. Es lo primero tras clonar un repo.

        
npm run devArranca el servidor local. Deja la terminal ocupada: eso es normal. Se corta con Ctrl+C.

        
npm uninstall gsapQuita una librería.

        
npx create-vitenpx corre sin instalar. Útil para generadores de proyecto que usas una sola vez.

      


      
Anatomía del package.json

      

        
package.json

        
{
  "name": "mi-proyecto",
  "scripts": {          // atajos: npm run dev
    "dev": "vite"
  },
  "dependencies": {     // lo que npm install reconstruye
    "gsap": "^3.12.5"
  }
}

05
let y const

      
RequierePseudocódigo

      
Una caja con nombre donde guardas un valor para usarlo después. let se puede volver a llenar; const se queda con lo que le pusiste.


      
Sintaxis

      

        
declarar

        
let contador = 0;        // va a cambiar
const COLOR = "#D2006B";  // no va a cambiar

contador = contador + 1;   // ✓ permitido
COLOR = "azul";            // ✗ error

      

      

        
Empieza siempre con const. Cámbialo a let solo cuando el programa te obligue. Así, al leer, sabes de un vistazo qué se mueve y qué no.

consola

06
Tipos de datos

      
Requierelet y const

      
Qué clase de cosa guardaste. El tipo decide qué operaciones tienen sentido: los números se suman, los textos se pegan.


      
Los siete que vas a ver

      

        
toca un valor para ver su tipo

        

          

          
Toca cualquiera.

        

      

      

        
Cuidado con las comillas: "42" es texto y 42 es número. Por eso "5" + 1 da "51" — JavaScript pegó dos textos en vez de sumar. Es el bug número uno al leer valores de un input.

      

      

        
convertir

        
const texto = "42";
Number(texto) + 1;   // 43  ✓
texto + 1;           // "421"  ✗

10
Loop

      
RequiereArraysCondicional

      
Repite un bloque de código varias veces, normalmente una por cada elemento de una lista.

      
Por qué te importaTodo lo generativo vive aquí: 500 partículas no se escriben 500 veces, se escriben una vez dentro de un loop.


      
Sintaxis · dos formas

      

        
for

        
// clásico: controlas el contador
for (let i = 0; i < colores.length; i++) {
  console.log(i, colores[i]);
}

// moderno: solo quieres los valores
for (const color of colores) {
  console.log(color);
}

      


      
Paso a paso

      

        
una vuelta a la vez

        

          

            
            
            
          

          

          

        

      

      
Loop infinito: si el contador nunca llega al límite, la pestaña se congela. Si pasa, ciérrala y revisa la condición del medio.

    


    
    

      
11
Función

      
Requierelet y constTipos de datos

      
Un bloque de código con nombre que guardas para usarlo cuando quieras. Recibe datos (parámetros) y normalmente devuelve un resultado (return).

      
EquivalenteUn componente o un símbolo: lo defines una vez, lo instancias muchas, y si le cambias algo adentro, cambian todos.


      
Sintaxis · dos formas, lo mismo

      

        
declarar y llamar

        
function area(ancho, alto) {   // parámetros
  return ancho * alto;      // devuelve
}

const area = (ancho, alto) => ancho * alto;   // arrow, igual

area(3, 4);   // 12  ← llamarla

      


      
Entra, sale

      

        
area(ancho, alto)

        

          

            

              
              
              
              
              

            

            

          

        

      

      
Sin return la función hace su trabajo pero no te entrega nada: al guardarla en una variable obtienes undefined. Y definir la función no la ejecuta — hay que llamarla con paréntesis.

12
DOM vs HTML

      
RequiereObjetosFunción

      
El HTML es el texto que tú escribiste y quedó guardado en el archivo. El DOM es el árbol vivo que el navegador construye a partir de ese texto — y es lo único que JavaScript puede tocar.

      
La diferencia en una líneaEl HTML es el archivo; el DOM es el documento abierto en el programa. Puedes mover todo dentro del documento y el archivo no cambia hasta que guardes… solo que aquí nunca guardas: al recargar, el DOM se reconstruye desde cero a partir del HTML.


      
Compruébalo

      

        
el HTML no se mueve, el DOM sí

        

          

            

              
index.html · lo que escribiste

  <h4>Nestor</h4>
  <p>Diseño</p>
</div>

              
Sin cambios.

Lo que vas a usar

      

        
tocar el DOM

caja.textContent = "otro texto";
caja.style.background = "#CFF25C";
caja.classList.add("activo");          // mejor: cambia la clase, no el estilo

const nuevo = document.createElement("p");
caja.appendChild(nuevo);

      

      
Si querySelector devuelve null: o el selector está mal escrito, o el script corre antes de que exista el elemento. Pon el <script> al final del body.

14
Lerp

      
RequiereFunciónTipos de datos

      
Interpolación lineal: dame el punto intermedio entre A y B según un avance t de 0 a 1. Con t = 0 estás en A, con 1 en B, con 0.5 justo a la mitad.

      
EquivalenteEs lo que hace el software entre dos keyframes. Tú pones A y B; el lerp calcula todos los cuadros de en medio.


      
La función completa

      

        
lerp

        
function lerp(a, b, t) {
  return a + (b - a) * t;
}

lerp(0, 100, 0.5);   // 50
lerp(0, 100, 0.25);  // 25

      


      
Mueve la t

Si en cada cuadro haces un lerp desde donde estás hacia el objetivo, obtienes persecución suave gratis. No hay duración ni curva definida: se acerca un porcentaje de lo que falta, siempre.

15
Easings

      
RequiereLerpFunciónLoop

      
Funciones que deforman el tiempo antes de interpolar. Reciben un t parejo de 0 a 1 y devuelven otro t, ya con aceleración. Eso es todo un easing: una línea de matemáticas.

      
Es literalLas curvas del editor de gráficos de After Effects son estas funciones. Cuando jalas los manubrios del bezier estás haciendo a mano lo que aquí se escribe en una línea.


      
Cómo se conecta con lo anterior

      

        
la cadena completa

        
// 1. t avanza parejo de 0 a 1 (el tiempo)
const t = tiempoTranscurrido / duracion;

// 2. el easing lo deforma
const easeOutCubic = (t) => 1 - Math.pow(1 - t, 3);

// 3. el lerp lo convierte en pixeles
x = lerp(0, 500, easeOutCubic(t));

      


      
Compáralas

      

        
curva, movimiento y números en sincronía

        

          

            

            

              

                
              

              

                

                

                contorno = linear
              

              

                t = 0.00
                eased = 0.00
              

              

                
                
              

              
            

          

          
Cuanto más vertical la curva, más rápido se mueve en ese instante. Lo plano al final es la desaceleración.

        

      


      

        
Cómo elegir: easeOut para cosas que entran o responden a un clic (arrancan rápido, aterrizan suave) — es el 80% de los casos en interfaz. easeIn para cosas que salen. easeInOut para movimientos largos entre dos puntos. back y elastic solo cuando la pieza pida carácter.

      

      
Lo único casi siempre incorrecto es linear: nada en el mundo físico arranca y se detiene de golpe. Si una animación se siente barata, empieza por ahí.
